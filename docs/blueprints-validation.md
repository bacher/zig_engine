# Blueprint implementation validation

This report accompanies the implementation of [the blueprint specification](../specs/features/blueprints.md). Capture and application are implemented; planning, rewards, sharing, NPC logistics, and applied-site cancellation remain outside this iteration.

## Implemented paths

- The selected capture frame, including the unconfirmed anchor frame, uses a faint `.greater` pass without depth writes before the normal opaque `.less_equal` depth-writing pass. Miniatures, diagnostics, and rails share one dynamic opaque instanced draw. A full-size application preview uses a separate cached instanced draw. The occluded-frame draw reuses the dynamic instances and adds only the selected frame's twelve rails, 144 triangles, in one extra draw. Miniatures, full-size application previews, and other active sites' frames receive no occluded-frame draw.
- All frames choose one continuous periodic X image using their middle cell. The renderer reuses its single chunk-relative conversion and subtracts the middle-cell offset before emitting the same twelve rails. There is no block traversal, second wrap calculation, split geometry, extra upload, or extra draw. Simultaneously visible opposite images of one site are outside this rendering scope; miniature and cached-preview coordinate policies retain their existing behavior.
- Full-size application previews upload packed local cell coordinates/materials once per selected immutable definition and tool generation. Camera/origin changes and quarter-turn rotations update uniforms without rebuilding or uploading source geometry; rotations move cell offsets while preserving world-aligned cube faces and texture orientation. An unavailable placement origin hides the preview while retaining its cache; replacement or leaving preview releases it. Miniatures, diagnostics, and rails retain their dynamic path.
- Capture immediately previews a 1×1×1 striped frame at the eligible unconfirmed anchor target. Hover and first-click confirmation share ordinary putting-target selection with 30-metre camera-to-nearest-cube-vertex reach, including adjacent physical placement and full-cell miniature targets. Hover does not create draft anchor/bounds, so Escape still opens the menu. Ordinary placement/mining remains at four metres; XY/height retain their raw-contact-from-feet metric.
- Escape while capture awaits its first anchor with the chooser closed leaves the tool and opens the ordinary game menu; Resume returns to ordinary play. After anchor selection, Escape discards the whole draft and stays in capture awaiting an anchor, where the next fresh Escape with the chooser closed opens the menu.
- B opens the saved-blueprint chooser from ordinary play or unanchored capture, or dismisses chooser/placement preview. A chooser over capture preserves capture mode/selection/generation; Cancel/Escape/B closes only that chooser, selecting a definition exits capture into placement preview, and an empty library leaves the current mode unchanged. Z controls capture, and Enter opens the validated capture name dialog; Enter in that dialog confirms the name and saves. B is ignored after anchor selection outside name entry. Ctrl+B toggles SSAO blur during ordinary play, capture outside name entry, and placement preview while modal/map input blocking remains in force. Bare B does not toggle blur, and F has no blueprint-tool binding.
- Client selection uses three fresh presses, a fixed XY plane outside the anchor-height camera slab and physical-hit adjacent-cell targeting inside that slab, then a frozen exact-contact/yaw vertical plane using absolute world/grid Z. XY stays one cell high; entering height selection may immediately jump to the actual contact height, and out-of-bounds absolute heights reject confirmation. The fallback skips miniatures and uses the 30-metre raw-contact range from current player feet rather than ordinary four-metre reach. Both paths preserve shortest wrapped X intervals and the world-dependent horizontal cap. Full-block source subscriptions are retained only through the single predicted-view copy. One reusable helper validates detached contents; cancellation generations prevent stale results from owning newer UI.
- The compiler normalizes materials, compacts the definition, applies only the narrowly eligible concrete-support cascade, and checks ordinary validity and cheap-rule assemblability. Successful cache entries no longer retain full failure diagnostics.
- Application copies versioned destination dependencies in bounded service turns, verifies physical targets and real bottom platforms, prepares complete footprint indexes on a helper, and publishes only after the existing dependency/overlay checks. Literal stone now requires a full platform for direct wood/mineral support and resets, making the compiler certificate portable to mixed real platforms. Apply reuses that certificate without structural target searches. Input covers the rotated box expanded by one cell along X/Y and three cells downward; cavity box chunks remain full index sources. Monotone additions preserve old valid cells without dependent enumeration or construction-marker copies. Road geometry remains omitted. Occupied/immutable targets, inadequate platforms, overlap, bounds, missing box sources and budgets still reject atomically. The [certified admission report](validation/blueprint-certified-admission.md) records current verification; the [target-only admission report](validation/blueprint-target-admission.md) and older symmetric-56 results remain historical.
- Client change packages preserve the original instance-publication/fulfillment order, so completing A before publishing a replacement B over its footprint no longer fails with overlap. This also applies when A is created earlier in the same package and to replacement chains. Definitions retain their existing staging/rollback. All fallible preparation and capacity reservation finish before ordered commit; staging leaves live indexes and earlier publication snapshots unchanged.
- Mixed-package staging uses expected O(1) hash lookups for staged instance IDs and preceding valid fulfillment identities, with scratch proportional to package instances and preceding valid fills. Publications clone only their footprint indexes and filter matching target identities in those owned clones. A nonempty fulfillment set adds one membership lookup per existing target in each cloned index; fills after the last instance add no overlay entries. Fulfillment-only packages remain allocation-free, with no whole-world/library copy or bitmap copy per fill. The five-neighbor structural path and O(1) completion are unchanged.
- Dedicated client and authority fulfillment reads at most five physical support cells. It does not call ordinary structural/dependent validation or road planning. Target removal, bit/counter updates, and known-empty construction insertion are incremental; completion does not scan the site.
- Completed-site retirement runs on every client world update after incoming chunk/blueprint-package reconciliation, including empty incoming queues, before gameplay/render work or GPU-capacity early returns; the service also retires metadata each normal worker turn. Each call visits at most four footprint chunks. Idle calls are allocation-free O(1); active work includes the existing per-chunk instance-ID search. Cleanup removes completed instance records and frees their bitmaps/footprints and unused chunk indexes while retaining library definitions and the replay ID high-water mark. An empty instance map restores ordinary validation's no-site fast path without adding fulfillment work.
- Ordinary removals protect real and indexed planned dependents in the completed logical world. Ordinary empty-cell insertions check the new physical/completed target without dependent enumeration or revalidation, using the additive-validity contract to preserve old cells. Client and authority share a dispatch that uses the ordinary physical-world validator when the instance map is empty, avoiding duplicate placement support searches and affected-cell collection. Retired sites awaiting cleanup conservatively keep the completed-world path. Adaptive-road effects from fills use a bounded coalesced queue. Formed and unformed roads have identical structural capabilities, so shape-only updates require no structural validator, `CompletedReader` pass, dependent collection, or above-road reads. The planner retains pattern, section-support, ownership, and immutable-write checks; source holds, reservations, and atomic publication remain. Ordinary material edits follow the insertion/removal distinction above. The [shape-neutral follow-up report](validation/monotone-block-additions.md) records current verification; the older AC115 results below describe the superseded shape-validation implementation. In-progress queue cursors survive metadata revisions, and completed dirty passes move to the tail for another pass so quiet entries progress. Every durable capture persists unfinished typed chunk keys with current world state, including ordinary/autosave, overdue, final, and internal journal-prefix captures; it does not require this queue to empty.
- The road queue owns deduplicated membership and a membership generation. A fill reserves keys before publication; completed work clears a key only after any coalesced repeat. Each capture owns one full canonical set, bounded to 4,096 five-byte keys. Marks, partial road results, and clears commit with world state. Load restores fresh cursor-zero entries directly from these keys before readiness, without scanning or preloading the world. Saved road state/ownership persists; cursor, observed revision, and repeat bookkeeping do not. The initial budget remains 16 seed/completion/requeue units per service turn, yielding on dependency/source/error waits. Saving adds no global road-drain hold; normal source gates and selected command prefixes still apply.
- Definitions, site progress, terrain, and inventory share world transactions. A fulfillment journal record is 13 bytes; progress does not clone the definition or full bitmap per fill. Authoritative acknowledgments remain individual while block snapshots coalesce within each service batch.
- Persistence preparation preallocates 16-byte ordered operations. Duplicate tracking uses the smaller of a touched site's bitmap and exact sparse indices, and releases this scratch after validation. Shared checked memory estimates cover payloads, containers, and state-table growth. Save preflight and constant-time journal admission also count the retained journal capacity and encoded changes. Backpressure drains accepted terrain/progress together before retrying new work; an in-flight job retains its encoded/prepared reservation until it finishes. A prepared application can wait for this drain and rechecks its dependencies before publication.
- A prepared application also survives a synchronous journal-capture startup failure. Explicit save retries, including coalesced ordinary requests from Retry or autosave, and the existing bounded final-save transient retry revisit it even when no writer was created, using the same publication/dependency checks as writer completion. Coalescing preserves the queued save's identity, original command fence, and automatic retry allowance. The wake check returns in constant time without allocations or unrelated queue scans when a writer is active. With no writer or application, it can resume the ready queued save or retained FIFO work; it adds no polling or per-block work.
- After a processed commit, writer termination wakes retained work through the existing path, including when later compaction fails. Uncommitted termination does not immediately retry journal-blocked applications/FIFO work or its drain. For journal-blocked work and nonzero command fences, the existing drain-failure policy retains one delayed final-save transient retry; ordinary saves, cancellation, and exhausted retries wait for an explicit request. The gate reads the lifecycle's existing finalizing stage before teardown.
- A distinct queued ordinary or final save with command fence zero can make its first capture attempt after an older writer fails or is canceled before commit. Its own queued status is published without inheriting the older error. The shared queued-drain helper performs the guarded existing query recheck and lifecycle readiness checks for pending reads, waiting queries, and compaction before capture; this uncommitted branch does not retry Apply/FIFO work. The handoff uses existing state and constant-time gating, with no new retry metadata, timers, polling, or per-block work.
- Save supports explicit idempotency keys for the lifetime of a client endpoint. Identical retries return the same definition ID; conflicting payloads/owners are rejected. Automatic fresh saves have a separate key namespace. A terminal rejection puts its still-current capture into the invalid state with a persistent reason and Escape restart guidance; a late reply cannot change a newer draft. Retryable persistence failures retain the service-owned payload. No reconnect or cross-session request-key protocol is part of this iteration.

## Budgets

These are technical budgets rather than additional material/geometry rules. Resource exhaustion rejects or defers before partial publication.

| Resource | Initial bound |
| --- | --- |
| Selected raw volume, including air | Configurable `Budgets.max_cells`, default 1,048,576; user approved |
| Retained full-block source chunks | Configurable capture budget, default 256 |
| Capture helper concurrency | One reusable worker, one input/result slot |
| Compiler validator cache | 8,192 compact entries plus bounded failure records; Apply has no structural validator |
| Application dependency snapshot | 1,024 chunks, 128 MiB conservatively estimated owned data |
| Service snapshot copy slice | Four chunks per turn |
| Concurrent application preparation | One service task, at most eight retiring tasks |
| Completed-site cleanup | At most four footprint chunks per client world update and normal service turn; idle calls are allocation-free O(1), active calls retain per-chunk ID-search cost |
| Deferred road work | 4,096 deduplicated typed chunk keys, five wire bytes each per capture; initially 16 seed/completion/requeue work units per service turn, yielding on dependency/source/error waits |
| Library/active-instance wire budgets | 4,096 definitions, 4,096 instances, 64 MiB durable state |
| Pending blueprint journal | 16 MiB, at most 1,048,576 operations; backpressure drains earlier accepted work |
| Save working memory | 64 MiB by default; includes journal capacity/growth, encoded changes, preparation, source encoding, and capture bookkeeping. Admission may drain before the wire/count limits. |
| Visible GPU instances | Combined dynamic and full-size preview limit of 1,100,000; miniatures use visible-chunk collection |
| Dynamic GPU instances | Lazy growth from 1,024, 48 bytes each; miniatures, diagnostics, and rails |
| Cached full-size preview | 16 bytes per occupied cell, uploaded once per selection; separate transform uniforms |

The independent horizontal limit remains `min(world_block_size_x / 2 - 1, world_block_size_y)` for each horizontal dimension. The 100×100×32 reference scenario fits the volume/source/snapshot budgets where world dimensions permit it.

For a dense 100×100×32 placement preview, packed source storage/upload is 5,120,000 bytes once per selection, replacing 15,360,000 bytes of full-size dynamic instances rebuilt/uploaded per frame. Warm draws update a 128-byte preview transform; dynamic rails and miniatures retain their separate uploads. These are representation/upload calculations, not measured FPS improvements. Each preview cube still submits 36 vertices; exposed-face culling remains deferred.
